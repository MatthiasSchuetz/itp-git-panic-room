# Commit Master

## Commit Messages

### Gut
- Fix issue #23 **Beschreibung: Man weiß genau wo der Fehler ist und was man damit machen muss.**
- Refactor code
- Add login validation **Beschreibung: Man weiß genau was man machen soll.**
- Remove unused imports
- Improve readability
- Improve performance
- Refactor Calculator for readability
- Update Calculator

### Schlecht
- Cleanup
- Update **Grenzfall: Man weiß nicht was geupdated werden soll, ich würde sie verbessern indem ich "Update ..." schreibe.**
- stuff **Beschreibung: Man hat keine Ahnung was man machen soll oder wo man etwas machen soll oder was sich geändert hat.**
- Fix bug **Grenzfall: Man weiß nicht um welchen Bug es sich handelt, ich würde sie verbessern indem ich "Fix ... bug" schreibe.**
- Temporary fix
- final version **Grenzfall: Man weiß nicht wovon es die Finale Version ist, ich würde sie verbessern indem ich "final version of ..." schreibe.**
- Small fixes
- Adjust logic
- Rename variables **Grenzfall: Man weiß nicht welche Variablen man umbenennen soll, ich würde sie verbessern indem ich "Rename variables: ...,...,..." schreibe.**
- Changes in app
- Add null check
- Handle edge cases


## Regeln für Commit Messages
1. Eindeutige Commit Messages(Hust hust Clemens)
2. Muss sich um den Inhalt handeln
3. Bei wiederholenden Messages - eigenen Branch erstellen und am Schluss Mergen (Bsp. Ganz oft style von Login bearbeiten)
